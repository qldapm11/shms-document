## A01.4 — Nhập tài khoản từ Excel

- **Mục đích:** Cho phép QTV tạo hàng loạt tài khoản (kèm hồ sơ nhân viên cơ bản) bằng cách tải lên file Excel, có bước kiểm tra dữ liệu trước khi ghi và báo cáo lỗi theo từng dòng, giảm công nhập tay khi khởi tạo hệ thống hoặc thêm khoa mới.
- **Vai trò sử dụng:** QTV (nhập liệu hàng loạt trong phạm vi được giao).
- **Liên kết nguồn:** A01.4; SCR-ADM-001 (Quản lý tài khoản, popup Nhập từ Excel, UI-REF-05-QT01); API-ADM-users-import (`POST /admin/users/import`).
- **Mức xác nhận:** PROPOSED (định dạng mẫu file, quy tắc validate 2 pha và cơ chế báo lỗi dòng do agent đề xuất; cần SA/PO xác nhận).

### Phạm vi
- **Làm:** (1) Tải mẫu file Excel chuẩn; (2) Tải lên file để kiểm tra (dry-run) không ghi dữ liệu; (3) Hiển thị kết quả kiểm tra: dòng hợp lệ / dòng lỗi kèm lý do; (4) Xác nhận nhập chính thức các dòng hợp lệ; (5) Tải báo cáo lỗi (các dòng không nhập được) để sửa và nhập lại; (6) Mỗi tài khoản tạo ra ở trạng thái ACTIVE với cờ `must_change_password`.
- **Không làm (giai đoạn này):** Nhập/cập nhật hàng loạt quyền chi tiết hoặc data-scope (A02.*); cập nhật hàng loạt tài khoản đã tồn tại (đề xuất giai đoạn sau — hiện chỉ tạo mới, dòng trùng bị báo lỗi); đồng bộ từ hệ thống nhân sự ngoài.
- **Phụ thuộc:** A01.1 (quy tắc tài khoản), A01.2 (hồ sơ nhân viên), A03.1 (danh mục khoa), A02.1 (vai trò mặc định để gán); bảng `platform.users`, `platform.staff_profiles`, `platform.user_roles`, `platform.files`, `platform.audit_logs`.
- **Giả định & câu hỏi:** Giả định định dạng `.xlsx`, kích thước ≤ 5MB, ≤ 2000 dòng/lần (đề xuất, cần xác nhận). Khoa và vai trò trong file tham chiếu bằng `code` (không phải id) để người dùng dễ nhập. Câu hỏi: nếu một dòng lỗi thì toàn bộ lô bị hủy hay chỉ bỏ qua dòng lỗi — đề xuất chế độ "nhập các dòng hợp lệ, bỏ qua dòng lỗi" và cho tải báo cáo lỗi; cho phép QTV chọn chế độ "tất-cả-hoặc-không" nếu cần.

### Luồng
- **Tiền điều kiện:** QTV đã đăng nhập có quyền `user.import`; đã tải và điền mẫu Excel đúng cấu trúc cột.
- **Luồng chính:** SCR-ADM-001 → "Nhập từ Excel" → tải mẫu (nếu cần) → chọn file `.xlsx` → tải lên → hệ thống đọc, validate từng dòng (dry-run) → hiển thị bảng kết quả: số dòng hợp lệ, số dòng lỗi (từng dòng ghi cột nào sai) → QTV xem, chọn chế độ nhập → "Xác nhận nhập" → hệ thống ghi các dòng hợp lệ trong một giao dịch, tạo `users` + `staff_profiles` + gán vai trò → ghi audit (1 bản ghi tổng + chi tiết số lượng) → hiển thị kết quả cuối + nút tải báo cáo lỗi.
- **Luồng thay thế (tất-cả-hoặc-không):** Nếu QTV chọn chế độ này và còn ≥1 dòng lỗi → không ghi gì, yêu cầu sửa file và nhập lại.
- **Ngoại lệ:** File sai định dạng/thiếu cột bắt buộc → 400 VALIDATION_ERROR (không xử lý); vượt kích thước/số dòng → 422 BUSINESS_RULE; username/email trùng với tài khoản đã có hoặc trùng trong cùng file → dòng bị đánh lỗi CONFLICT; khoa/vai trò `code` không tồn tại → dòng lỗi; mất kết nối giữa chừng → giao dịch rollback, không tạo bản ghi dở.
- **Hậu điều kiện:** Các dòng hợp lệ được tạo thành tài khoản ACTIVE + must_change_password; file gốc lưu ở `files` (tham chiếu kiểm toán); `audit_logs` ghi lô nhập (người thực hiện, tổng/hợp lệ/lỗi, file ref); báo cáo lỗi sẵn sàng tải.

### Hành động
| Hành động | Quyền | Điều kiện cho phép | Tác động | Phản hồi |
|---|---|---|---|---|

| Tải lên & kiểm tra (dry-run) | QTV (`user.import`) | file đúng định dạng, trong giới hạn | validate, không ghi DB | bảng kết quả hợp lệ/lỗi |

### Trạng thái
- Phiên nhập có pha: UPLOADED → VALIDATED → (COMMITTED | REJECTED). Dry-run dừng ở VALIDATED; chỉ "Xác nhận nhập" chuyển sang COMMITTED.
- Chống thao tác trùng: `Idempotency-Key` cho POST import để tránh ghi 2 lần khi nhấn lại; khử trùng trong file (username/email/employee_code lặp lại trong cùng file bị đánh lỗi); ghi ghi DB theo giao dịch để tránh dữ liệu dở.
- Mỗi tài khoản tạo ra theo vòng đời A01.1 (ACTIVE). Không xóa cứng; nếu cần hủy phải khóa/ngừng dùng từng tài khoản.

### Dữ liệu / API / quyền
- **Dữ liệu:** `platform.users`, `platform.staff_profiles`, `platform.user_roles`, `platform.files`(id, owner_id, path, mime, size, checksum) lưu file gốc, `platform.audit_logs`.
- **API (API-ADM-users-import):**
  - `GET /admin/users/import/template` → file mẫu.
  - `POST /admin/users/import?dryRun=true` (multipart file) → `{ summary:{total, valid, invalid}, rows:[{index, status, errors:[{column, code, message}]}] }` (không ghi DB).
  - `POST /admin/users/import` (multipart file, mode=SKIP_INVALID|ALL_OR_NOTHING; header `Idempotency-Key`) → `{ created, skipped, errors, fileRef }`.
  - Lỗi: 400 VALIDATION_ERROR (file/cột), 403 FORBIDDEN, 422 BUSINESS_RULE (vượt giới hạn / ALL_OR_NOTHING có lỗi).
- **Quyền:** QTV có `user.import` + data-scope khoa; dòng có `department_code` ngoài data-scope bị đánh lỗi quyền (không tạo). File chứa dữ liệu cá nhân — không ghi mật khẩu thô trong file; MK tạm sinh server-side theo A01.3.

### Kiểm thử (Given–When–Then)
- **Thường:** GIVEN file 10 dòng hợp lệ WHEN dry-run THEN 10 hợp lệ, 0 lỗi, chưa ghi DB; WHEN xác nhận THEN tạo 10 tài khoản ACTIVE + audit lô.
- **Thường:** GIVEN file 10 dòng, 2 dòng trùng username WHEN dry-run THEN 8 hợp lệ 2 lỗi CONFLICT đúng số dòng.
- **Lỗi:** GIVEN file thiếu cột `employee_code` WHEN tải lên THEN 400 VALIDATION_ERROR, không xử lý dòng nào.
- **Lỗi:** GIVEN chế độ ALL_OR_NOTHING và có 1 dòng lỗi WHEN xác nhận THEN 422, không tạo bản ghi nào.
- **Biên:** file 2000 dòng → xử lý; 2001 dòng → 422; file 6MB → 422.
- **Quyền:** GIVEN QTV data-scope khoa A WHEN file có dòng department_code khoa B THEN dòng đó đánh lỗi quyền, không tạo.
- **Tích hợp:** GIVEN import thành công WHEN tài khoản mới đăng nhập lần đầu THEN bị buộc đổi mật khẩu (A01.3 must_change_password).
- **Chống trùng:** GIVEN cùng `Idempotency-Key` WHEN gọi xác nhận 2 lần THEN chỉ tạo 1 lần.

### Nghiệm thu & tài liệu
- **Nghiệm thu:** Dry-run báo đúng dòng hợp lệ/lỗi kèm lý do theo cột; nhập chính thức ghi đúng theo chế độ chọn; giao dịch đảm bảo không dữ liệu dở; file gốc lưu kiểm toán; báo cáo lỗi tải được; tài khoản mới buộc đổi MK; test quyền/giới hạn/chống trùng PASS.
- **Tài liệu cập nhật:** hướng dẫn chuẩn bị file Excel + bảng mã khoa/vai trò; hướng dẫn QTV nhập hàng loạt và xử lý báo cáo lỗi; liên kết A01.1/A01.2/A02.1.
